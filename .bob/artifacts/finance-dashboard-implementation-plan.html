Key principle: Services are isolated behind a contract interface so the data source can be swapped (yahoo-finance2 → proxy → mock) without touching any component. Hooks are the only layer that call services — components are always data-in / events-out.

3 Data Service Abstraction

financeService.js

Public contract. Components and hooks only import from here. Exposes fetchQuotes(symbols) and fetchHistory(symbols, window).

yahooFinanceAdapter.js

Implements the contract using yahoo-finance2. Maps raw Yahoo responses to a normalised shape: { symbol, price, change, pct, history[] }.

mockData.js

Static fixtures matching the normalised shape. Used by tests and triggered via VITE_USE_MOCK_DATA=true for offline demos.

Yahoo Finance practical note

yahoo-finance2 works server-side (Node). For the browser, add a lightweight Express proxy under server/proxy.js and configure Vite's proxy option to forward /api/finance requests. This avoids CORS and keeps the browser bundle clean.

// financeService.js — public contract
export async function fetchQuotes(symbols)           // current-day snapshot
export async function fetchHistory(symbols, window)  // 7d or quarter OHLCV

// yahooFinanceAdapter.js — implementation detail
import yahooFinance from 'yahoo-finance2';
// normalises → { symbol, price, change, pct, history[] }

4 Charting Approach

Recommended Recharts v2 — ships as a React-native component set, tree-shakeable, well-maintained, and straightforward to mock in Vitest/JSDOM (no canvas dependency).

ViewChart typeNotes
Current day<BarChart> + summary cardsNo intraday history in free Yahoo tier — cards are more reliable for single-day data
Last 7 days<LineChart> multi-seriesOne line per company, 7 data points, shared <Legend>
Last quarter<AreaChart> multi-series~63 trading-day points, transparent fill to avoid overlap clutter

All three views consume the same PriceChart component — the chart type is passed as a prop, keeping the dashboard panels uniform and the bundle small.

5 State Management Strategy

No global state library is needed for V1. The data model is shallow and co-located:

HookState shapeScope
useMarketData(window){ loading, error, quotes, history }DashboardPage — all tracked companies
useCustomTicker(symbol){ loading, error, data }CustomTickerPanel — single user symbol
Selected time windowuseState('today')DashboardPage
Upgrade path: Introduce @tanstack/react-query if caching between window switches becomes important, proxy calls are slow and need background refresh, or the Part-2 ticker lookup needs debouncing and request deduplication.

6 Error Handling

LayerMechanismWhat it catches
Component boundary<ErrorBoundary> wraps <DashboardPage>Unexpected render exceptions
Hook leveltry/catch in useEffect, sets error stateNetwork failures, Yahoo 429 rate limits, malformed JSON
Service levelAdapter throws typed errors: DataUnavailableError, SymbolNotFoundErrorAllows hook to distinguish and display the right message
Security rule: User-facing messages must never expose stack traces or internal API details. Show "Data unavailable for IBM — please try again." not the raw error string.

8 Local Validation Steps

These match exactly what .github/workflows/finance-app-ci.yml runs in CI, so local and remote gates are identical.

npm install          # 1. Install dependencies

npm run lint         # 2. Catch style and security issues early

npm test             # 3. All unit + component tests (Vitest)

npm run build        # 4. Production build — confirms no bundler errors

npm run dev          # 5. Dev server — manual visual check only

Add a single convenience script to package.json:

"scripts": {
  "validate": "npm run lint && npm test && npm run build"
}

Bob runs npm run validate as the single gate before every commit.

9 GitHub-Driven Feature Evolution

One-file extension points

Every extension path is a minimal, reviewable diff:

  • Add a company: edit only src/constants/tickers.js — no component changes.
  • Swap the data source: implement a new adapter in src/services/, change one import in financeService.js.
  • Add a time window: add an entry to TimeWindowTabs props and a getDateRange() case.
  • Add a chart type: add a new PriceChart variant; no dashboard logic changes.
